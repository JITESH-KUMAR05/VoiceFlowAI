# CLAUDE.md

Working rules for this repository. Read before making changes.

## What this project is

An outbound voice agent. It places a real PSTN call through Twilio, runs a
consultative sales conversation using Azure OpenAI, speaks with streamed Murf
TTS, then scores the lead and writes the result to Salesforce.

Two agent personas ship: B2B SaaS qualification and real-estate lead
qualification. Both share one pipeline and differ only in system prompt,
greeting, and voice.

It is a portfolio project built by one person. It is not an enterprise product,
and nothing in the repository may claim otherwise.

## Non-negotiable rules

### 1. Never display a number the system did not produce

No placeholder metrics, no illustrative KPIs, no "1,247 calls today". Every
figure rendered in the UI traces to a backend response or is absent. When there
is no data, render an empty state that says so.

This is the rule most likely to be violated by accident. A stat card needs a
number to look finished, and inventing one is the path of least resistance.
Don't. An honest zero is worth more than a plausible fabrication, and a reviewer
who catches one invented number stops trusting the rest of the project.

### 2. Never claim a capability the code does not implement

No "SOC 2 compliant", no "end-to-end encrypted", no "enterprise-grade", no
uptime or scale claims. Describe what the code does, in the words an engineer
would use to describe it.

### 3. There is no mock data

`src/data/mockData.ts` is gone and must not come back. Every view reads from
`src/lib/api.ts` and renders an explicit empty state when the API returns
nothing.

If a view genuinely cannot be wired yet, it renders `SampleDataNotice` from
`src/components/DataState.tsx` so the placeholder is visible on screen rather
than only in the source. A view that silently shows invented records is the
failure this rule exists to prevent.

### 4. Secrets never enter the repository

Config comes from the environment via `backend/app/config.py`. `.env` is
gitignored. `.env.example` lists every key with an empty value and a comment.
Never paste a live credential into source, docs, tests, or a commit message.

## Design rules

The frontend was originally generated by Lovable and carried that tool's default
aesthetic. That look is what made the project read as machine-made. These rules
exist to keep it from returning.

**Forbidden:**

- Gradient fills on text, buttons, icons, or cards
- Glow effects, `box-shadow` used as decoration, backdrop-blur "glass" surfaces
- Ambient background orbs, `float`, `pulse-glow`, `shimmer` animations
- Entry animations on page load — no staggered fade-in-up on every element
- Emoji as UI iconography (fine in Markdown prose, not in the interface)
- More than one accent hue in a single view

**Required:**

- **Type:** IBM Plex Sans for prose and UI. IBM Plex Mono for anything
  machine-generated: call SIDs, phone numbers, durations, latencies, timestamps,
  scores, JSON. The mono/sans split is the primary way this UI signals what is
  data and what is chrome.
- **Color:** neutral warm grays carry the interface. The accent marks
  interactive affordances only. Saturated color is reserved for semantic state —
  green for a live call, red for a failed one, amber for a warning. If a color
  does not mean something, it should not be there.
- **Density:** this is an operations console. Tables are compact and scannable.
  Prefer a tight row over a roomy card when showing many records.
- **Motion:** functional only. Layout shifts, state transitions, and loading
  indicators. Motion explains a change; it does not announce a page.
- **Elevation:** shadows only where something genuinely floats — popovers,
  dropdowns, dialogs. Flat surfaces use borders.

Both themes are hand-tuned. Light is the default. Every token is defined on bare
`:root` and redefined under the dark selector — never define a color only inside
a media query or `[data-theme]` block.

## Architecture

```
backend/
  app/
    main.py            FastAPI app factory, middleware, lifespan
    config.py          Pydantic Settings — fails fast on missing required keys
    routers/           HTTP surface, one module per concern
    services/          External integrations (Twilio, Azure OpenAI, Murf,
                       Salesforce, SMTP). One class per provider.
    models/            Pydantic request/response schemas
  tests/               pytest, no network — providers are faked at the boundary

voiceflowFrontend/
  src/
    lib/api.ts         Single source of backend URL and every fetch call
    components/ui/     shadcn primitives — edit only to change design tokens
    components/        Feature components
    pages/             Route components
```

### Rules that follow from it

- **Routers hold no business logic.** They parse, delegate to a service, and
  shape the response.
- **Services never import from routers or `main`.** Dependencies point one way.
- **No component calls `fetch` directly.** All network access goes through
  `src/lib/api.ts`, which reads `VITE_API_BASE_URL`. A hardcoded
  `http://localhost:8000` anywhere else is a bug — it breaks every deployment.
- **In-memory state is bounded.** Session and audio caches carry a TTL and a
  size ceiling. An unbounded module-level dict is a memory leak.

## Testing

`pytest` from `backend/`. Tests must run with no network and no credentials —
provider clients are faked at the service boundary.

Cover the logic that is actually yours: persona and prompt selection, the
scoring contract, session lifecycle and eviction, webhook signature rejection,
TwiML shape. Do not write tests that assert Twilio's SDK works.

## Commits

Conventional Commits. Imperative subject, under 72 characters.

```
feat(api): validate Twilio webhook signatures
fix(ui): read API base URL from env instead of hardcoded localhost
refactor(backend): split main.py into routers
docs: rewrite README setup for the app-factory layout
test(services): cover session eviction under TTL expiry
```

Scope the body to *why*, not *what* — the diff already says what. One logical
change per commit; do not mix a redesign with a bug fix.

## Before claiming work is done

Run the checks and read the output. Do not report success from expectation.

```bash
cd backend && uv run pytest -q
cd voiceflowFrontend && npm run lint && npx tsc -b --force && npm run build
```

`tsc -b`, not `tsc --noEmit`. The root `tsconfig.json` sets `"files": []` and
only holds project references, so a bare `tsc --noEmit` typechecks nothing and
exits 0 no matter how broken the code is.

Current baseline: 35 backend tests passing, 0 lint errors, 0 type errors. The
9 remaining lint warnings are `react-refresh/only-export-components` in the
shadcn primitives, which is inherent to how those files are written.

If something fails, say so and show the failure. A partially working change
reported as complete is worse than an honest broken one.
