# VoiceFlow AI — Production Hardening Design

**Date:** 2026-08-26
**Status:** Approved (phases 1–4)

## Problem

The project's engineering substance and its presentation are badly mismatched.

The backend does real integration work: outbound PSTN calls via Twilio, streamed
TTS through Murf, Azure OpenAI for both conversation and post-call scoring, and
a Salesforce sync that writes to nine custom Lead fields. That last part in
particular is not something you can fake — it requires having actually built the
Salesforce object model.

The frontend undoes it. It was generated by Lovable and still carries that
tool's signature: neon cyan-to-emerald gradients, glow shadows, glass cards,
staggered entry animations on every element. Worse, it displays fabricated
metrics ("1,247 Total Calls Today", "342 Qualified Leads") and an outright false
compliance claim ("SOC 2 compliant with end-to-end encryption").

A reviewer who notices one invented number discounts everything else in the
repository. The fabrications are a larger credibility problem than the styling.

The backend has its own defects that a competent reviewer finds quickly:
permissive CORS in an invalid configuration, unauthenticated Twilio webhooks,
an unbounded in-memory cache, `print` in place of logging, unpinned
dependencies, and no tests.

## Goals

- No rendered value that the system did not produce
- No claimed capability the code does not implement
- A visual language that reads as a deliberately designed operations console
- A backend a reviewer can navigate, run, and trust
- Documentation that explains design decisions, not just setup steps

## Non-goals

- New product features. Nothing here adds agent capability.
- Rewriting working integrations. The Twilio, Murf, OpenAI, and Salesforce
  service code is sound; it gets structure and error handling, not replacement.
- Authentication or multi-tenancy. Out of scope for a demo, and pretending
  otherwise would violate the honesty rule this document exists to enforce.

## Phase 1 — Credibility

Remove everything untrue.

- Delete the fabricated stat row and the SOC 2 / end-to-end-encryption claims
  from `pages/Index.tsx`
- Drop `lovable-tagger` from `package.json` and `vite.config.ts`; rename the
  package from `vite_react_shadcn_ts`
- Confine `mockData.ts` to the three components that still read it, each marked
  visibly as sample data
- Add `backend/.env.example` with every key, empty, commented

Smallest phase, largest credibility return per line changed.

## Phase 2 — Backend

Restructure `backend/` into an `app/` package. `main.py` is currently 363 lines
mixing routing, prompt construction, persona tables, and persistence.

```
app/
  main.py          app factory, middleware, lifespan
  config.py        Settings; fails fast when a required key is missing
  logging.py       structured logging setup
  personas.py      voice map + prompt construction, extracted from main
  session.py       TTL-bounded conversation and audio caches
  routers/         calls, telephony, crm, audio, health
  services/        unchanged interfaces, error handling added
  models/          request/response schemas
```

**Security fixes:**

- CORS restricted to a configured origin list. The current
  `allow_origins=["*"]` with `allow_credentials=True` is a combination browsers
  reject outright — it is not merely permissive, it is broken.
- Twilio webhook signature validation via `RequestValidator`. Without it,
  anyone who discovers the ngrok URL can drive the call flow and burn API
  credit.
- Session and audio caches bounded by TTL and entry ceiling.

**Reliability:** timeouts and typed failures on every outbound provider call;
`logging` in place of `print`; pinned dependency versions; a health endpoint
reporting per-provider configuration status.

**Tests:** `pytest`, no network, no credentials. Providers faked at the service
boundary. Coverage targets the logic that is genuinely this project's — persona
selection, prompt construction, scoring contract, session eviction, webhook
signature rejection, TwiML shape.

## Phase 3 — Frontend

**Design tokens.** Replace the generated system. IBM Plex Sans for interface,
IBM Plex Mono for machine-generated values — call SIDs, durations, latencies,
scores. That split is the main signal distinguishing data from chrome. Neutral
warm grays carry the interface; one accent marks interactive affordances;
saturated color is reserved for semantic state. Radius tightens from `0.75rem`
to `0.375rem`. Gradients, glows, glass, and ambient orbs are removed outright.
Light and dark are both hand-tuned, light default. (Today `:root` and `.dark`
hold identical values, which is itself a tell.)

**API layer.** `src/lib/api.ts` becomes the only module that performs network
access, reading `VITE_API_BASE_URL`. Ten files currently hardcode
`http://localhost:8000`, which breaks every deployment.

**Landing page.** Replaced by a system overview: what the agent does, an
architecture diagram of the call path, and the design tradeoffs behind it —
streamed TTS to cut time-to-first-audio, in-memory sessions and why that is a
deliberate limitation. Then links into the two consoles.

**States.** Every data view gets explicit loading, empty, and error states.
Fetches currently have no error path; a failed request renders as a silently
empty table.

## Phase 4 — Documentation

README rewritten for the new layout, with an honest limitations section. A short
architecture document covering the call sequence and the decisions worth
defending in an interview: why streaming TTS, why in-memory session state, why
weighted scoring instead of asking the model for a number.

## Risks

**Regression during restructure.** The backend has no tests today, so Phase 2
begins by writing them against current behavior, then restructures underneath.

**Scope creep in Phase 3.** Twenty-plus page and component files could each
absorb unbounded polish. Design tokens land first, so most components improve
without being individually touched; only components that are structurally wrong
get rewritten.

**Live credentials.** Real keys were pasted into a chat transcript and written
to `backend/.env`. The file is correctly gitignored and no `.env` has ever been
committed, but the keys should be rotated before the repository is shared.
